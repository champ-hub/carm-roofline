# CARM Test Bench - Architecture and Implementation

This document describes the architecture and implementation of the CARM microbenchmark test bench, a high-precision measurement harness for CPU floating-point and memory performance analysis.

## Execution Timeout

`run_microbenchmarks()` computes the execution timeout from the physical byte-transfer cost
of each benchmark, not from a fixed 100 ms/benchmark assumption:

- **Memory benchmarks** (non-zero `read_array_size` + `write_array_size`): estimated as
  `(bytes_per_thread × num_threads × effective_runs) / 1 GB/s` where
  `effective_runs = NUM_RUNS + CALIBRATION_START_REPS`.  The 1 GB/s floor is intentionally
  conservative to cover NUMA cold-fault storms (caused by `MADV_DONTNEED` before each benchmark),
  QEMU simulation slowdown, and cross-NUMA accesses.
- **Arithmetic benchmarks** (zero-byte arrays): fallback of 100 ms × effective_runs (matches the
  C calibration target).
- A **10× safety factor** is applied to the summed estimate, then clamped to a 60-second minimum.

**Why `CALIBRATION_START_REPS`?** The C wrapper begins every benchmark with `CARM_BENCH_START_REPS = 100`
repetitions in the very first calibration function call before any proportional scaling occurs.
For a 512 MiB DRAM benchmark, those 100 initial reps transfer 100 × 512 MiB regardless of
`NUM_RUNS`.  With `test_time=1` → `NUM_RUNS=10`, the first calibration iteration alone can exceed
the entire measurement budget, causing a timeout.  Adding `CALIBRATION_START_REPS` extra equivalent
runs to the per-benchmark estimate reserves time for this worst-case first iteration.

**Why not `test_time × N × 5` (original)?** That formula assumed each benchmark took ~`test_time` seconds
and ignored calibration entirely.  For DRAM benchmarks with 512 MiB+ working sets and a small
`test_time`, the calibration overhead dominates and 5× margin was insufficient.

## Architecture Overview

The new test_bench (v2) uses a **wrapper-based inline measurement approach** to eliminate function pointer indirection while maintaining type safety and code organization:

- **Generator** ([test_bench/builder.py](builder.py)) renders the `microbenchmarks.h` header from function specs produced by [benchmark/generation/isa.py](../benchmark/generation/isa.py). The header contains inline microbenchmark functions (e.g., `x86_fma()`, `arm_neon_add()`) and a `MICROBENCHMARK_LIST` macro.
- **Wrapper system** ([test_bench/wrapper.inl](wrapper.inl)) creates `wrapper_<benchmark_name>` functions that contain the full measurement logic (calibration, synchronization, timing) and directly call the inline benchmark.
- **Main entry point** ([test_bench/test_bench.c](test_bench.c)) orchestrates threading, result aggregation, and CSV output.
- **Shared definitions** ([test_bench/test_bench.h](test_bench.h)) provides type definitions, global variables, and helper functions visible to both test_bench.c and wrapper.inl.

**Key advantage**: Each wrapper function contains the measurement code and directly calls the inline benchmark function (e.g., `x86_fma(data_ptr, reps)`), achieving true zero-overhead execution. The compiler inlines the benchmark directly into the wrapper's measurement loop, eliminating all function pointer indirection.

**Critical implementation details**:
- **Volatile timestamps**: `t_start` and `t_end` are declared `volatile` to prevent compiler optimization from reordering or batching timing calculations. Without this, the compiler may defer elapsed time calculations, causing systematic accumulation errors.
- **Explicit serialization**: Architecture-specific memory barriers (`lfence`, `dsb sy`, `fence`) ensure pipeline draining before/after timing measurements.

## Core Features

### Threading & Affinity
- One pthread per logical thread
- Per-thread CPU affinity set via `pthread_attr_setaffinity_np()` before `pthread_create()`
- **Block mapping** (default): Thread `i` is pinned exclusively to `thread_affinity[i]` - one CPU per thread, no overlap
- Thread mapping is determined by the benchmark's metadata, generated by the python layer
### Per-Thread Input Buffer Layout
- `array_size_bytes` metadata is interpreted as **bytes per thread**
- A single shared allocation is sized to the **maximum** `align_up(read + write, 64) * num_threads` across all benchmarks in `MICROBENCHMARK_LIST`
- Each thread receives a distinct pointer: `base + tid * aligned_stride`
- Every per-thread chunk is 64-byte aligned, avoiding cache-line overlap across thread buffers

### NUMA Page Placement
- The single shared buffer is reused across all benchmarks in sequence. Without intervention, physical pages placed on NUMA node 0 by one benchmark would be silently accessed as remote memory by a subsequent benchmark whose threads run on node 1.
- `run_all_benchmarks()` calls `madvise(combined_buffer, combined_total, MADV_DONTNEED)` **before every benchmark**. On `MAP_ANONYMOUS | MAP_PRIVATE` mappings (which glibc uses for large allocations), this immediately discards all physical pages. The next access by each thread triggers a fresh page fault, and the kernel allocates the new physical page on the faulting thread's local NUMA node.
- This ensures correct first-touch NUMA placement for every benchmark regardless of run order.

### Priority Management
- Process niceness set to `PRIO_MIN (-20)` during benchmarking via `setpriority()`
- Restored to normal priority (0) after completion

### Synchronization
- Two-barrier approach using `pthread_barrier_wait()`:
  - Coordination before/after calibration phase
  - Synchronization before/after each measurement run
- Frequent `sched_yield()` before timed regions to reduce scheduling jitter

### Serialization
- **x86**: `lfence` before/after timed paths and around TSC reads
- **ARM**: `dsb sy` memory barrier
- **RISC-V**: `fence` instruction

### Timing Sources
- **x86**: Cycle-accurate timing with `rdtsc` (start) and `rdtscp` (end) + `lfence` serialization
- **ARM/SVE/RISC-V**: `CLOCK_MONOTONIC` via `clock_gettime()` for wall-time measurement

### Frequency Input
- Frequency measurement is handled **externally** (removed from test bench)
- `--freq` argument is **required** and provided by the caller
- No internal frequency probing or clock tests

### Repetition Calibration
- **Algorithm**: Matches legacy behavior
  1. Start with `reps = 1`
  2. Multiply by 10 until elapsed time > 100ms (sufficient time)
  3. Compute optimal reps: `ceil(EXPECTED_TIME * freq * test_reps / measured_time)`
  4. All threads synchronize and use the maximum reps across threads
- **Target runtime**: 100ms (100,000,000 ns)
- **Configurable**: Can be adjusted via `EXPECTED_TIME_NS` macro
- **Calibration margin**: Uses 120% overshoot (1.2x `CARM_BENCH_MIN_CAL_TIME_NS`) to avoid oscillation near threshold
- **Anomaly detection**: Retries measurements if elapsed time drops >20% unexpectedly (context switch detection)
- **Minimum reliable time**: Below 1ms, uses conservative 10x scaling instead of proportional scaling

### Measurement Loop
- Run `NUM_RUNS` (default: 32) iterations
- Each iteration:
  - Synchronize all threads via barrier
  - Serialize (architecture-specific memory barrier)
  - Time benchmark execution using volatile timestamps
  - Serialize again
  - Record per-thread timing
  - Synchronize via barrier

### Thread Aggregation
- **x86**: For each run, find min cycle start and max cycle end across threads
  - Run duration = `max_end - min_start`
  - Accounts for slight thread skew
- **ARM/SVE/RISC-V**: For each run, take max wall-time across threads
  - Conservative measurement (slowest thread determines run time)

### Result Calculation
- Median computation across NUM_RUNS iterations
- Uses qsort-based median calculation with averaging for even-length arrays

### Output Format
- Per-benchmark: `test_id, median_ms, num_reps` (one line per benchmark to stdout)
All architectures output milliseconds (conversion from cycles is done internally for x86)
Diagnostic/error messages to stderr

## Timing Stability Considerations

The benchmark harness implements several mechanisms to ensure stable, reproducible timing measurements:

1. **Volatile timestamp variables**: Prevents compiler from optimizing away or reordering timing calculations
2. **Explicit serialization**: Memory barriers ensure pipeline quiescence before/after measurements
3. **Calibration overshoot**: 120% margin prevents oscillation when approaching target time
4. **Anomaly detection**: Rejects measurements with >20% variance (detects context switches)
5. **Minimum time threshold**: Conservative 10x scaling for sub-millisecond calibration iterations
6. **Process priority**: PRIO_MIN (-20) during benchmarking reduces scheduler interference

These combine to produce timing variance typically <5% across runs, matching legacy benchmark stability.

## Architecture-Specific Details

### x86 Implementation
- **Timing**: TSC (Time Stamp Counter) via `rdtsc`/`rdtscp`
- **Serialization**: `lfence` instruction
- **Output**: Cycles (not milliseconds)
- **Frequency**: Used for nominal vs. real comparison (both set to same value in v2)

### ARM/SVE Implementation
- **Timing**: `clock_gettime(CLOCK_MONOTONIC)`
- **Serialization**: `dsb sy` (Data Synchronization Barrier - System)
- **Output**: Milliseconds
- **Working set**: SVE scales by `VLEN * VLMUL` (when applicable)

### RISC-V/RVV Implementation
- **Timing**: `clock_gettime(CLOCK_MONOTONIC)`
- **Serialization**: `fence` instruction
- **Output**: Milliseconds
- **Working set**: RVV scales by `VLEN * VLMUL` (when applicable)

## Build Configuration

- **Compiler flags**: `-Ofast -pthread -lm`
- **Warnings**: `-Wall -Wextra`
- **Debug verbosity**: Add `-DVERBOSITY=4` to see calibration steps and timing details
- **NUM_RUNS**: Define at compile time (default: 32)
- **EXPECTED_TIME_NS**: Define at compile time (default: 100000000 = 100ms)
- **CARM_BENCH_MIN_CAL_TIME_NS**: Minimum calibration time (default: 50000000 = 50ms)
- **CARM_BENCH_MIN_RELIABLE_TIME_NS**: Minimum time for proportional scaling (default: 1000000 = 1ms)

## Generator Integration (benchmark/generation/)

The benchmark generator produces a single C header (`microbenchmarks.h`) in a temporary writable workspace containing:

1. **Inline function definitions**: Static inline, always-inline microbenchmark functions (e.g., `x86_fma(void *data_ptr, uint32_t num_reps)`)
2. **Metadata + affinity arrays**: Each benchmark emits a `benchmark_metadata_t` plus a dedicated static `int[]` CPU affinity array; `.thread_affinity` stores a pointer to that array.
3. **Wrapper instantiation**: Each benchmark uses the pattern:
   ```c
   #define UBENCH_NAME x86_fma
   #include "wrapper.inl"
   #undef UBENCH_NAME
   ```
   This creates `wrapper_x86_fma()` containing full measurement logic
4. **MICROBENCHMARK_LIST macro**: X-macro pattern for dispatching all benchmarks:
   ```c
   #define MICROBENCHMARK_LIST \
       X(wrapper_x86_fma, "x86_fma") \
       X(wrapper_x86_avx2_fma, "x86_avx2_fma") \
       X(wrapper_x86_sse_fma, "x86_sse_fma")
   ```

The wrapper.inl file contains the complete measurement template:
```c
static void *wrapper_<NAME>(void *arg)
{
    thread_wrapper_data_t *tdata = (thread_wrapper_data_t *)arg;
    void *data_ptr = tdata->data_ptr;

    /* Volatile timestamps prevent compiler optimization */
    volatile uint64_t t_start = 0;
    volatile uint64_t t_end = 0;

    /* Calibration phase with proportional scaling */
    uint64_t reps = CARM_BENCH_START_REPS;
    while (!sufficient_time) {
        serialize();
        t_start = carm_bench_time_start();
        UBENCH_NAME(data_ptr, reps);  // Direct inline call
        t_end = carm_bench_time_end();
        serialize();
        elapsed_ns = carm_bench_elapsed_units(t_start, t_end, tdata->freq);

        /* Anomaly detection: retry if time drops >20% */
        if (prev_elapsed_ns > 0 && elapsed_ns < prev_elapsed_ns * 0.8) {
            continue;
        }

        /* Proportional scaling with guards */
        if (elapsed_ns < CARM_BENCH_MIN_RELIABLE_TIME_NS) {
            reps *= 10;  // Conservative scaling for sub-millisecond times
        } else {
            reps = carm_bench_calculate_cal_reps(elapsed_ns, reps);  // 120% overshoot
        }
    }

    /* Measurement loop with volatile timestamps */
    for (int i = 0; i < NUM_RUNS; i++) {
        barrier_sync();
        serialize();
        t_start = carm_bench_time_start();
        UBENCH_NAME(data_ptr, num_reps);  // Direct inline call
        t_end = carm_bench_time_end();
        serialize();
        tdata->elapsed_ns[i] = carm_bench_elapsed_units(t_start, t_end, tdata->freq);
        barrier_sync();
    }
}
```

**Flow**: Main dispatches via X-macro → Each thread executes wrapper function → Wrapper directly calls inline benchmark → Zero overhead measurement

**Include hardening**: `test_bench.c` includes `microbenchmarks.h` with angle brackets (`#include <microbenchmarks.h>`), and the compile step places generated include directories before `test_bench/` in `-I` order. This prevents an in-tree `test_bench/microbenchmarks.h` from shadowing the generated header in the temporary workspace.

**How inlining works**: The compiler sees `UBENCH_NAME(data_ptr, reps)` as a direct call to the static inline benchmark function and optimizes it into the wrapper's loop, achieving the same performance as hand-written assembly-embedded loops while maintaining better code organization.
